## План единой системы

1. **P0 — этот patch:** закрыть ложные подтверждения, отделить current session от reusable contract, сохранить POST boundary, вернуть зелёный полный CI. Опубликовать только проверенный SHA и сверить deployment/logs.
2. **P1 — PAGE_ACCESS:** разбить REQUEST, OWNER_APPROVE, OPERATOR_ASSIGN на независимые действия. Для каждого: exact target, текущий actor, checkpoint до POST, verification прав после. Chromium остаётся для получения неизвестного/устаревшего контракта и необходимых интерактивных подтверждений.
3. **P2 — РК и FP:** переносить исполнение по одному контракту. Capture должен блокировать отправку до сохранения intent. HTTP verification не принимает запрошенный URL или кэш за доказательство. При неизвестном результате сначала reconcile, затем разрешённый retry; новый CREATE требует отрицательного подтверждения предыдущего результата.
4. **P3 — Payment:** отделить read-only funding inspection и настройку валюты/timezone от submit карты. Ограниченный browser lease только для полей/подтверждений, которые требуют формы. Результат — точная funding relation нужного РК, а не успешное нажатие кнопки.
5. **P4 — orchestration:** Desired state → planner → независимые jobs → transport executor → VERIFY → COMMIT. Cache минимум 30 минут; transient sync failure сохраняет последнее достоверное состояние. READY_TO_LAUNCH требует реальных прав и funding, а запуск выполняет fresh preflight.
6. **Release gate:** backend regression без пропусков + Node/PHP UI/payment/sync guards → один проверенный SHA → Railway deployment → конкретный job trace по каждому этапу. Работу остальных профилей не останавливает manual_required одного профиля.

Переход выполняется в существующем engine и storage, без параллельной альтернативной системы. Неизвестный ответ остаётся неизвестным; защита от дублей сохраняется.

## Верификация

Локально проверяются новые причинные сценарии и смежные lifecycle/Prepare/Page/RK tests. Полная обязательная проверка выполняется GitHub workflow `Meta provisioning regressions`: backend без пропусков и Node guards, отдельно и параллельно — PHP payment/install/sync guards. Так падение backend больше не скрывает дефекты оплаты и установки UI. Локальная среда без установленного Chromium не заменяет этот gate.

Этот аудит не выдаёт synthetic tests или health 200 за успешное создание полного комплекта в Meta. Устранение Meta BUSINESS_LOGIN_GATE и отказа 1357054 должно быть подтверждено новым реальным trace; такого trace на момент исходного аудита нет.
