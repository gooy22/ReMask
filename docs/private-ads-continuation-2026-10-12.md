# Private advertising continuation

The post-28fdfb9 implementation described in the user's report was not found in
available working directories, saved files, open PRs or 208 repository branches
(205 distinct heads checked). It may still exist in another execution environment.

The exact public source was recovered from 28fdfb9: all 12 script hashes and all
38 selected full-module hashes match. Vendor bundles and session credentials are
not committed. Evidence metadata is in private-ads-source-recovery-20261012.json.

The new private protocol supports a first PAUSED image-ad path through the
existing PrivateLaunchService, worker task and Jobs UI. It resolves the existing
managed Media Library, rehashes the opened file, uploads with AdsBulkUploadImages'
multipart shape, verifies the returned image/account, creates three draft levels,
polls the saved publication handle, then independently reads Campaign, AdSet,
Ad and Creative with exact IDs, account, parents, settings, Page and media.

The existing Launch journal stores atomic submission claims and sanitized receipts.
Unknown replies block POST replay. Pending publication resumes READs; terminal
publication does not mark the task successful until object verification completes.
The actor and complete adapter code digest bind each saved launch.

Source research did not record actual request/response bodies or establish the
fresh initializer layout. Bootstrap only accepts supported literal fresh ServerJS
configuration/ApiClient setter calls. Missing/conflicting configuration stops before
mutation. The captured origin/version are defaults; SDK-routed browser URLs remain
unconfirmed. A usable profile proxy and live canary remain necessary.

Video, Instagram, selected Pixel/audience assets and activation are not
enabled by this first image adapter and fail during preparation. Existing Relay
fixtures and old durable launches are preserved; launch keys cannot mix protocols.
The deployed manifest still controls which protocol is selected.

Local checks before the execution environment disconnected: 30 new synthetic tests
and a combined 109-test advertising/HTTP2/old Launch run passed. The connected image
path adds seven tests; its final validation is performed in GitHub CI.
No Meta advertising, payment or bank mutation was submitted during development.

The continuation also connects PAUSED image carousels (2–10 cards) through the
same draft publisher. Each managed image upload is journaled by its checksum;
resumption reads saved receipts and never replays a lost response. Existing image
hashes require exact account-scoped reads. Card order, destinations, headlines,
descriptions and CTA are preserved and independently checked in the final Creative.
Automatic card reordering and the generated end card are explicitly disabled.

The carousel schema is derived from three additional modules in the original,
hash-verified scripts, recorded in private-ads-carousel-source-20261012.json.
Invalid downstream fragment values now fail before media uploads. Ten carousel
lifecycle cases and three read-only bootstrap audit cases were added. The optional
REMASK_LAUNCH_HTTP_AUDIT_ADS_BOOTSTRAP mode checks only the fresh selected-account
document; it does not query payment settings, submit advertising or export session
credentials. A real initializer/publication proof is still required.
